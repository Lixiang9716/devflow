# Skill: analyst-phase1 — Requirements Analysis & Specification

## Name
analyst-phase1

## Purpose
Convert natural language requirements into structured specifications: use cases (L0→L1), functional/non-functional requirements (FR/NFR), and Lean acceptance criteria.

## Input
- User requirement (natural language, any language)
- Optional: existing documentation, legacy system description
- Knowledge context (positive + negative from T11)

## Output
- `UseCase` objects (YAML, L0→L1 with alternative flows)
- `Requirement` objects (FR-XX, NFR-XX with traceability to UC)
- `AcceptanceCriterion` objects (Lean AC format: {given, when, then})
- Traceability matrix (UC→FR→AC)
- Known unknowns declaration

## Lean AC Rules (MANDATORY)
1. AC = {given, when, then} — three elements, nothing more
2. One AC = one assertion (single comparison in `then`)
3. `then` MUST be quantifiable (contains `==`, `<`, `>`, `in`, `matches`, `raises`)
4. NO fuzzy words in `then`: 正常, 正确, 合理, should, maybe
5. Unquantifiable AC → method=MANUAL, mark as technical debt
6. Test code generated by tool, not handwritten
7. AC tests submitted as part of same patch as business code

## Failure Handling
- Ambiguous requirement → request_clarification → wait for Human
- Knowledge context empty (cold start) → seed_generate then continue
- Validation fails → iterate until valid then proceed
